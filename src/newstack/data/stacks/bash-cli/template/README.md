# {{ title }}

A word-count-style CLI in plain bash, generated by newstack. It counts lines,
words and bytes the way `wc -l -w -c` does, and it does the counting in bash
itself — no `wc`, no `awk`, no `od`.

## Requirements

`bash` 4.4 or newer. Nothing else.

## Run it

```
./bin/{{ npm_name }} --help
./bin/{{ npm_name }} sample.txt
./bin/{{ npm_name }} -l sample.txt
./bin/{{ npm_name }} sample.txt second.txt
printf 'alpha beta\ngamma\n' | ./bin/{{ npm_name }} -w
printf 'alpha beta\ngamma\n' | ./bin/{{ npm_name }} -w -
```

```
 2  4 23 sample.txt
2 sample.txt
 2  4 23 sample.txt
 1  1  4 second.txt
 3  5 27 total
3
3 -
0.1.0
```

The same file through `wc -l -w -c`:

```
 2  4 23 sample.txt
```

## Exit status

| code | meaning |
| ---- | ------- |
| 0 | everything was counted (also `--help`, `--version`) |
| 1 | at least one file could not be read |
| 2 | the arguments made no sense |

With no operand the tool reads standard input, and that row carries no name —
`wc` only labels the row when it was given an operand, and `-` is an operand.
A missing file is reported on standard error, prints no row of its own, and
still lets the `total` row through when another operand was read — the same
thing `wc` does.

## Layout

```
main.sh              entry point: sources the library, runs, exits
lib/counts.sh        byte counting and column formatting
lib/options.sh        hand-rolled argv parser
lib/io.sh             the only file that touches files, stdin, stdout, stderr
lib/runner.sh         rows, the shared width, the total row, the exit status
bin/{{ npm_name }}    wrapper so the tool runs from any directory
tests/               94 assertions, no test framework
```

Three deliberate choices:

- **The counter never sees the file system.** `textstat_counts_of_data` takes the
  bytes as a string and leaves the figures in globals, so the arithmetic is
  testable without fixtures.
- **One module owns the process.** `lib/io.sh` is the only place that reads or
  writes anything, and `lib/runner.sh` calls it through four functions. The tests
  replace those four with buffers, which is how they assert on what a user would
  actually see.
- **Bytes are bytes.** `main.sh` exports `LC_ALL=C`, so `${#data}` counts bytes
  rather than characters and `héllo wörld` is 14 bytes, not 11 characters.

## Tests

```
bash tests/run_tests.sh
```

```
checks: 94, passed: 94, failed: 0
```

The suite covers the counting core, the parser, and the runner, including exit
statuses and stderr text. Standard input is faked in the unit tests; the
`stdin` check in `stack.json` and in the shipped workflow is what proves the real
pipe path, so keep both.

## Lint

```
shellcheck -x main.sh lib/*.sh bin/* tests/*.sh
```

`.shellcheckrc` switches off the three checks that only fire because the library
files are sourced into one program (`SC1091`, `SC2034`, `SC2154`).
