# {{ title }}

A small JSON web service built with [Cask](https://com-lihaoyi.github.io/cask/) on
Scala 3, generated by `newstack`. It counts lines, words and bytes the way `wc`
does, and answers every request with JSON.

## Getting started

```sh
scala-cli test .                                  # 14 utests
mkdir -p bin && scala-cli --power package . -o bin/{{ npm_name }}.jar --assembly -f
PORT=8080 java -jar bin/{{ npm_name }}.jar
```

Then:

```sh
curl 'localhost:8080/stats?text=hello%20world%0A'
curl -X POST -H 'content-type: application/json' \
     --data-binary '{"text":"a b\nc\n"}' localhost:8080/stats
```

## The contract

| Request | Answer |
| --- | --- |
| `GET /health` | `200 {"status":"ok"}` |
| `GET /stats?text=...` | `200 {"text":...,"lines":N,"words":N,"bytes":N}` |
| `POST /stats` with `{"text":"..."}` | same as above |
| `GET /stats` without `text` | `422 {"error":"missing_text",...}` |
| `POST /stats` with non-string `text`, or a body that is not a JSON object | `422 {"error":"missing_text",...}` / `422 {"error":"invalid_json",...}` |
| any other path | `404 {"error":"not_found","detail":"no route for GET /nope"}` |
| a known path with an unsupported method | `405 {"error":"method_not_allowed"}` |

Counting rules: a line is one `\n` byte, a word is a maximal run of non-space
characters, and bytes are UTF-8 bytes — so `"héllo wörld\n"` is 1 line, 2 words
and **14** bytes, not 12. Plenty of `wc` reimplementations get that one wrong.

Text is counted exactly as sent: nothing trims, folds or normalises whitespace,
because the same code path serves the tests, the CLI probe and the socket.

## Layout

| Path | What lives there |
| --- | --- |
| `project.scala` | `scala-cli` directives: Scala 3.3.7, Cask, uPickle, uTest |
| `src/{{ package_name }}/Counts.scala` | `Counts` and `Counts.of(text)` — the counting rules |
| `src/{{ package_name }}/Contract.scala` | `Contract.route(method, path, query, body) -> Reply` — all routing, no I/O |
| `src/{{ package_name }}/Server.scala` | the Cask layer: one catch-all route that delegates to `Contract` |
| `test/ContractTests.scala` | 14 utest cases over the pure contract |

The split matters: `Contract` is a pure function, so the whole HTTP surface is
covered without a socket, and `Server` only translates Cask's `Request` into
four strings.

## Two Cask facts worth knowing

`@cask.route` wants **lowercase** method names. `Seq("GET", "POST")` compiles,
matches the path, and then answers 405 to everything. And a single catch-all
route needs the path `"/"` with `subpath = true`; the `"/[...]"` form matches
nothing at all. A handler that takes only `Request` makes Cask try to bind
unknown query parameters, which fails with `Unknown argument: "text"`, so the
handler also takes a `QueryParams` that swallows them.
